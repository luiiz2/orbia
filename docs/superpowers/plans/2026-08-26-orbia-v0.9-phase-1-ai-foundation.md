# Orbia v0.9 Phase 1 AI Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the reusable AI core, provider adapters, task routing, privacy enforcement, secure credentials, and settings integration required by later Orbia v0.9 features.

**Architecture:** Shared AI contracts describe capabilities, providers, models, routes, privacy modes, and sanitized errors. Main-process adapters own HTTP calls and provider-specific payloads; `AiCoreService` owns route resolution, capability checks, fallback, and privacy enforcement. Existing `app_settings` stores non-secret AI configuration, while an `ai_credentials` table stores only `safeStorage`-encrypted secrets. The existing Settings screen consumes a narrow IPC bridge and never receives credentials.

**Tech Stack:** Electron Main/preload IPC, TypeScript, `better-sqlite3`, native `fetch`, Electron `safeStorage`, React, Zustand, i18next, Vitest.

## Global Constraints

- Implement PHASE 1 only: AI CORE + PROVIDERS + TASK ROUTING + PRIVACY.
- Do NOT implement transcription, RAG, semantic search, summaries, or chapters yet.
- Do not spread provider-specific calls throughout the application.
- `LOCAL_ONLY` must technically prevent cloud invocation below the UI level.
- Cloud fallback must NEVER happen silently when privacy configuration prohibits it.
- Do not automatically send transcripts, notes, PDFs, materials, course names, or user metadata to cloud providers without configured permission.
- Use secure credential storage appropriate to the existing Electron architecture; never log API keys.
- Reuse the existing settings table and Settings UI patterns; do not create a settings framework.
- The application remains usable when no local AI server is running.
- Do not add dependencies or refactor unrelated features.
- Preserve the existing Electron main/renderer security boundary and do not expose secrets, raw provider payloads, or filesystem paths to Renderer.
- Run focused tests after each cohesive task, then `npm test`, `npm run typecheck`, `npm run lint`, and `npm run build` for final integration.
