# Orbia v0.8 Phase 1 — Source Foundation TDD Plan

**Parent plan:** `docs/superpowers/plans/2026-08-24-orbia-v0.8-connected-library.md`

**Scope:** Implement only the generic source contracts and the lossless Vault database migration/backfill. Do not add adapters, sync, resolver, player, OAuth, cache behavior, IPC, or UI in this phase.

## Constraints

- Preserve every existing canonical and user-data row and ID.
- Retain legacy path columns as the v0.8 compatibility projection.
- Never move, delete, or rewrite user media.
- Create a recoverable database backup before backfilling a non-empty v0.7 library.
- Keep the migration idempotent and contained in one SQLite transaction after backup.
- Add no dependency.

## Task 1 — Source domain contracts

Files:

- Create `src/types/source.ts`.
- Modify `src/types/index.ts` only to export the new contracts.
- Create `test/sources/source-types.test.ts`.

TDD steps:

1. Add a test asserting the exact supported provider and availability values and their exported TypeScript contracts.
2. Run `npx vitest run test/sources/source-types.test.ts` and verify RED because the source module/exports do not exist.
3. Add the minimum shared types and readonly value sets for source definitions, roots, items, canonical links, match candidates, offline assets, sync runs, provider locators, technical metadata, and explicit availability.
4. Run the focused test and `npm run typecheck` to verify GREEN.

## Task 2 — Lossless source-schema migration

Files:

- Modify `src/main/services/database.service.ts` only in migration setup and a focused private backfill helper.
- Create `test/sources/source-migration.test.ts`.

TDD steps:

1. Add a fresh-database test for the seven source tables, required indexes, constraints, and migration marker `007_v08_connected_library`.
2. Add a simulated-v0.7 test containing a course, module, lesson, resource, progress, note, bookmark, flashcard, Library Studio appearance, Discovery row, and optimizer provenance row.
3. Snapshot every pre-existing row and ID; reconnect to trigger migration; assert snapshots are byte-for-byte equivalent after migration.
4. Assert one deterministic local source item/link is created for every legacy lesson and resource, with the exact legacy path retained in the source locator and canonical path column.
5. Assert `PRAGMA foreign_key_check` is empty, reconnect is idempotent, and a `.v0.8.bak` database backup exists for the non-empty migration.
6. Run `npx vitest run test/sources/source-migration.test.ts` and verify RED because the tables and marker do not exist.
7. Implement the minimum schema, indexes, checkpointed backup, transactional deterministic backfill, and assertions needed to pass.
8. Run the focused migration test, source-type test, existing database/studio/optimizer migration tests, then `npm run typecheck`.

## Review checkpoint

- Inspect the complete diff for source/canonical boundary leaks.
- Confirm no existing canonical table or path column is altered or dropped.
- Confirm deleting a source link cannot cascade into deleting canonical lessons/resources.
- Confirm migration failure cannot leave the marker recorded without complete backfill.
- Run `git diff --check`.
- Stop after reporting this phase; do not start adapters without the next phase checkpoint.
