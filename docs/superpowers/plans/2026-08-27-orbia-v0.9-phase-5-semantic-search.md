# Orbia v0.9 Phase 5: Semantic Search, Find in Library, Related Content

## Scope

Implement only semantic search, hybrid search, Find in Library, direct source
navigation, useful library filters, and optional related content. Preserve the
existing deterministic `courses.searchGlobal` path and the v0.6 Discovery
engine. Do not implement summaries, chapters, or AI notes.

The semantic path is explicit and local-index based: typing updates the
existing normal-search state only; embedding is requested only after the user
submits a semantic/hybrid search or asks for related content. AI/provider
failure falls back to lexical indexed results and never disables normal search.

## Contracts and deterministic ranking

Files:

- `src/types/library-search.ts`
- `src/types/index.ts`
- `src/main/services/retrieval/retrieval-ranking.ts`

Add shared request/result contracts for `normal`, `semantic`, and `hybrid`
search modes; filters for course, module, content type, vault, transcript,
materials, and notes; grouped result kinds; safe ID-based navigation metadata;
index coverage and `semanticUsed` state; and related lesson/material/course
groups. Keep physical paths out of the new IPC result contracts.

Expose a configurable deterministic fusion limit for search while retaining
the grounded-chat default cap of eight. Tie-break equal scores by stable chunk
or entity ID.

## Main search and related-content services

Files:

- `src/main/services/search/library-search.service.ts`
- `src/main/services/search/search-ranking.ts` (only if a separate search
  projection is needed)
- `src/main/services/search/index.ts`
- `src/main/services/semantic-index/semantic-index-repository.service.ts`
  (only for narrowly scoped metadata/source lookup additions)

Implement `LibrarySearchService.search(input)` with these rules:

1. `normal` delegates to the existing database search behavior; do not alter
   `DatabaseService.searchGlobal`.
2. `semantic` and `hybrid` resolve the active vault scope, query the current
   local semantic index, apply filters, and use deterministic lexical/semantic
   fusion. A missing, building, partial, or failed index returns empty grouped
   results plus coverage; it never calls the embedding provider when no usable
   completed generation exists.
3. A provider/embed error keeps lexical results and reports
   `semanticUsed: false`.
4. Map transcript/subtitle chunks to timestamp locators, PDF chunks to page
   locators, and code/material chunks to file and line locators. Group results
   by course, lesson, transcript, materials, PDF, code, and enabled notes.
5. Apply course/module/content-type/vault/note filters before final ranking and
   cap work/results to bounded values suitable for a large index.

Implement `LibrarySearchService.related(input)` as a supplemental read-only
projection over semantic-index neighbors. Aggregate chunk neighbors into
related lessons, materials, and courses with deterministic scores, exclude the
anchor entity, honor scope/filter settings, and return empty/partial coverage
when semantic indexing or the provider is unavailable. It must not call or
modify Discovery.

## Safe direct navigation

Files:

- `src/main/services/search/library-search-navigation.service.ts`
- `src/main/ipc/search.ipc.ts`
- `src/main/ipc/index.ts`
- `src/types/api.ts`
- `src/preload/index.ts`

Validate result IDs and live ownership in Main before returning a navigation
target. Return only canonical course/module/lesson/resource/note IDs and
bounded timestamp/page/line data. Add explicit `search:find-in-library`,
`search:related`, and `search:resolve-result` channels. Keep
`courses:search-global` unchanged. The resolver must reject deleted,
mismatched, invalid, or unsupported sources.

new raw filesystem paths across the new search bridge.

## Tests

Add focused tests in:

- `test/library-search.test.ts` for exact normal-search compatibility,
  paraphrase/hybrid ranking, transcript timestamp, PDF page, code line,
  filters, no-result, incomplete index, unavailable provider, and large-index

  validation.
- `test/search-ipc.test.ts` and/or renderer store/component tests for IPC
  parsing, explicit-submit behavior, and grouped UI data handling.

Run the focused search regression tests first, then `npm test`, `npm run
typecheck`, and `npm run lint`. Preserve unrelated dirty files and report any
pre-existing failures separately.

## Verification checklist

- Existing exact `course/module/lesson` search remains unchanged.
- Semantic/hybrid search is optional, deterministic enough to assert, and
  independent of AI availability for normal search.
- Search typing produces no embedding/provider call.
- Results retain original source identity and locators.
- Related content supplements Discovery without changing Discovery code.
- No summaries, chapters, or AI notes are added.
