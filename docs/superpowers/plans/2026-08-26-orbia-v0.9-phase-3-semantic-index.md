# Orbia v0.9 Phase 3 — Semantic Index Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add on-demand, versioned local semantic indexing for supported Orbia text sources using the existing AI router, SQLite database, persistent background queue, and minimal status controls.

**Architecture:** Main-process extraction produces provenance-complete source documents, a pure chunker creates natural-boundary chunks, and a semantic-index service batches text through `AiCoreService.embed()`. SQLite stores immutable index generations, normalized chunks, and `Float32` vector BLOBs; the existing optimization queue carries durable semantic-index jobs and the existing worker/resource gate executes them.

**Tech Stack:** Electron Main/Preload/React, TypeScript, `better-sqlite3`, `mupdf` already present in the repository, existing `AiCoreService`, `OptimizationQueueService`, `OptimizationWorkerService`, `ResourceManagerService`, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-26-orbia-v0.9-phase-3-semantic-index-design.md`

## Global Constraints

- Implement PHASE 3 only: content extraction, chunking, embeddings, semantic index, and related controls.
- Do not implement AI Chat, RAG retrieval, semantic search queries/results, summaries, generated chapters, or OCR for scanned PDFs.
- Reuse `AiCoreService.embed()`; `LOCAL_ONLY` must never reach a cloud embedding adapter.
- Reuse `OptimizationQueueService`, `OptimizationWorkerService`, and `ResourceManagerService`; do not create a second queue or resource manager.
- Keep source identity canonical and path-independent; never duplicate source text into queue payloads.
- Notes remain excluded unless the vault setting is explicitly enabled.
- Add only focused regression tests; do not add coverage-only tests or replace removed tests with equal/larger volume.
- Preserve unrelated dirty-worktree changes and never touch `vazados/`.
