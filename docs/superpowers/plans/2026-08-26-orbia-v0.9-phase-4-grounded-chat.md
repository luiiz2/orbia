# Hybrid Retrieval, Grounded Chat and Source Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add scoped hybrid retrieval, grounded local conversations and validated source navigation over the existing Phase 3 semantic index.

**Architecture:** The Main process validates scope, retrieves lexical and compatible semantic candidates from the vault SQLite database, builds a bounded prompt containing untrusted source data, calls only `AiCoreService`, and persists the answer plus retrieval-owned source snapshots. The renderer uses a typed preload bridge and a reusable chat panel; it never selects sources, accesses SQLite/filesystem paths, or trusts model citations.

**Tech Stack:** Electron 39, React 19, TypeScript 5.9, `better-sqlite3` with FTS5, Zustand, Vitest, existing `AiCoreService`, `DatabaseService`, semantic-index repository, player seeking and PDF/material viewers.

**Spec:** `docs/superpowers/specs/2026-08-26-orbia-v0.9-phase-4-grounded-chat-design.md`

## Global Constraints

- Implement Phase 4 only: hybrid retrieval, grounded chat, conversations and source navigation.
- Do not implement summaries, generated chapters, semantic-search results UI, retranscription, re-embedding or an external vector database.
- Keep `DatabaseService` as the vault SQLite owner and keep `AiCoreService` as the only embedding/chat provider entry point.
- Use the current semantic-index generation only; never mix provider, model, dimension or chunking versions.
- Enforce scope and source navigation in Main; renderer input is untrusted.
- Treat transcript, PDF, code and note text as untrusted data inside an explicit prompt delimiter.
- Under `LOCAL_ONLY`, reject cloud embeddings and cloud chat before any provider invocation.
- Return `insufficient_evidence` without a model call when the indexed scope has no usable support.
- Store source text once in semantic chunks; conversation source rows store provenance snapshots, not copied chunk bodies.
- Preserve existing canonical IDs, player seeking, media-source abstraction, PDF infrastructure and persistent optimization queue.
- Keep tests focused on business behavior and integration boundaries; do not add render-only or mock-call-only tests.

- [ ] **Step 3: Add bounded reciprocal-rank fusion and vector math**

Implement `fuseRankedCandidates` with a fixed reciprocal-rank constant and deterministic tie-breaking by chunk ID. Decode only finite Float32 vectors with the expected dimension and calculate cosine similarity; zero-length or malformed vectors are discarded. Add a proximity adjustment only when a chunk belongs to `request.moment.lessonId` and its stored time interval overlaps or is nearest to the requested timestamp.

```ts
export function fuseRankedCandidates(
  lexical: RankedCandidate[],
  semantic: RankedCandidate[],
  limit: number
): RankedCandidate[] {
  const scores = new Map<string, RankedCandidate>()
  for (const [rank, candidate] of lexical.entries())
    addRank(scores, candidate, 1 / (60 + rank + 1))
  for (const [rank, candidate] of semantic.entries())
    addRank(scores, candidate, 1 / (60 + rank + 1))
  return [...scores.values()]
    .sort(
      (a, b) =>
        b.relevanceScore - a.relevanceScore ||
        a.chunkId.localeCompare(b.chunkId)
    )
    .slice(0, Math.max(1, Math.min(limit, 8)))
}
```
