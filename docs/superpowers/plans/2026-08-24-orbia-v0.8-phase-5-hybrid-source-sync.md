# Orbia v0.8 Phase 5 Hybrid Source Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconcile local and app-owned source inventories into SQLite, preserve every canonical/library-organization record, and support manual, startup, periodic, and debounced watcher-triggered synchronization.

**Architecture:** `SourceSyncService` consumes provider-neutral batches from registered Main-process adapters and commits one complete root snapshot through `SourceRepositoryService`. The repository updates source tables only, preserves item IDs across unambiguous fingerprint renames, marks absent items missing instead of deleting them, and records sanitized sync runs. `SourceWatchService` treats watcher events only as dirty hints and schedules full root reconciliation with a periodic fallback.

**Tech Stack:** Electron 39, TypeScript 5.9, Node.js `fs.watch`/timers/crypto, better-sqlite3, Vitest.

**Status:** Implementado diretamente na branch `main`. A fase também serializa create/open/delete de Vault e aguarda sincronizações ativas antes de trocar ou fechar a base.

**Spec:** `docs/superpowers/plans/2026-08-24-orbia-v0.8-connected-library.md` sections 12, 16, 24, 25, 29, 30, and implementation phase 5.

## Global Constraints

- Never rename, move, overwrite, or delete user media.
- Source reconciliation may mutate only `content_sources`, `source_roots`, `source_items`, and `source_sync_runs`; it must never update canonical titles, canonical IDs, module relationships, Library Studio appearances, progress, notes, history, or canonical source links.
- Missing provider items remain persisted and become `missing`; links are retained.
- A rename/move preserves a source item ID only when one unmatched existing item has the same non-empty fingerprint; ambiguous fingerprints never auto-link.
- Watch events are hints only. Every hint is debounced and followed by inventory comparison.
- Errors persisted or logged by this phase are fixed sanitized messages without paths, locators, tokens, or provider payloads.
- Main-only locators never cross IPC. Renderer IPC receives only IDs, counts, timestamps, and source summaries.
- Use Node.js standard APIs and existing dependencies only.
- Work directly on `main`, as explicitly requested by the user.

- [x] **Step 3: Implement minimal orchestration**

`SourceSyncService` must:

```ts
public async syncRoot(rootId: string, trigger: SourceSyncTrigger): Promise<SourceSyncResult> {
  const root = this.repository.getRoot(rootId)
  if (!root) throw new Error('Unknown source root')
  const adapter = this.getAdapter(root.locator.provider)
  const run = this.repository.beginSync(rootId, trigger, this.now())
  try {
    const items: SourceSnapshotItem[] = []
    for await (const batch of adapter.reconcile({ root: root.locator })) items.push(...batch.items)
    return this.repository.completeSync(run.id, items, this.now())
  } catch {
    this.repository.failSync(run.id, this.now())
    throw new Error('Source synchronization failed')
  }
}
```

Adapters map scanner fingerprints and provider-owned stable identities. Local identity is the slash-normalized root-relative path; managed identity is `assetId`. Do not use raw filenames to construct managed paths.

`SourceManagerService` owns one `SourceSyncService` and delegates adapter lookup through its existing registry. Register only `LocalFolderSourceAdapter` on the global manager in this phase; managed registration remains explicit until its cache-root resolver exists.

`LocalFolderSourceAdapter.watch()` uses `fs.watch(root.path, { recursive: true })`; the callback emits only `{ reason: 'changed' }`. If recursive watch creation throws, return a no-op disposable and rely on periodic sync.

`SourceWatchService` lists roots through the manager, keeps disposables by root ID, and treats all events as hints. It never derives mutations directly from `eventType` or filename. `registerSourcesIpc()` starts the singleton coordinator once and registers both list and manual-sync handlers.

IPC validation:

```ts
function requireSourceRootId(value: unknown): string {
  if (
    typeof value !== 'string' ||
    value.length === 0 ||
    value.length > 512 ||
    /[\u0000-\u001f\u007f]/.test(value)
  ) {
    throw new Error('Invalid source root ID')
  }
  return value
}
```
